===== 第 1 頁 =====

資訊檢索與生成式人工智慧

學期專題一
網頁搜尋引擎
繳交期限：2026 年 11 月 12 日


1  目標與範圍

建立一個小規模、聚焦特定主題的網頁搜尋引擎。蒐集公開網頁，對文字進行前處理，建立倒排索引，並透過簡單的網頁介面提供經過排序的檢索結果。本作業要求的系統採用傳統資訊檢索方法；不要求使用大型語言模型（LLM）、嵌入向量（embeddings）、檢索增強生成（RAG）或生成式回答。

• 了解爬蟲如何發現網頁，以及如何遵守爬取限制。
• 實作倒排索引、TF-IDF 權重計算及餘弦相似度排序。
• 使用人工判定的相關性與 Precision@5 評估搜尋品質。


2  網頁爬蟲

• 選擇一個明確的主題，以及 5–10 個種子網址（seed URLs）。明確列出允許爬取的主機名稱白名單；若使用子網域，也必須將其列入。只追蹤此範圍內的連結，重新導向也必須遵守這項範圍限制。
• 蒐集 200–1,000 個主要文字內容非空的有效網頁。以正規化後不重複的網址計算頁數，不計入失敗的請求。若所選網站無法提供 200 個合適的網頁，請調整種子網址。
• 只爬取公開的 HTTP/HTTPS HTML 網頁。排除登入頁面、受 CAPTCHA 驗證碼保護的頁面、下載檔案，以及需要 JavaScript 渲染的頁面。不得繞過存取限制。
• 遵守 robots.txt，並使用可識別爬蟲身分的 User-Agent。對同一主機發出的請求之間，至少間隔兩秒，併發請求也適用；若網站要求更長的延遲，必須遵守。
• 設定請求逾時時間（例如 10 秒），以及網頁擷取嘗試總次數上限（例如 3,000 次，包含失敗的嘗試）。避免反覆重試；收到流量限制回應時，應停止或延長等待時間後再嘗試。記錄失敗情況與略過的網址。
• 在檢查已造訪網址集合之前，先將相對網址解析為絕對網址，並移除 #fragment 片段識別符。進階的內容去重功能為選做項目。不要任意移除查詢參數，因為它們可能用來識別不同頁面。（例如，https://ex.com/course.html 與 https://ex.com/course.html#grading 是同一個頁面。）
• 擷取網址、標題、主要文字與擷取時間。在可行的情況下，移除程式腳本、樣式與明顯的導覽文字。使用 JSON 或 SQLite 儲存蒐集的資料，欄位為 {url, title, text, fetch_time}。


===== 第 2 頁 =====

3  文字處理與索引建立

• 使用英文網頁可讓實作最簡單。也允許使用中文或混合語言的文件集合，但報告必須說明中文斷詞方法，以及各語言適用的前處理方式。
• 文件與查詢必須採用一致的前處理流程。在適當情況下轉為小寫、進行斷詞，並記錄停用詞處理政策。應謹慎處理標點符號：避免將 machine-learning 這類字詞合併成 machinelearning，並說明如何處理 C++ 這類詞彙。
• 為文件指派文件 ID，並建立倒排索引，將每個詞彙對應至包含文件 ID 與詞頻的倒排串列（postings）。儲存排序所需的文件頻率與文件向量範數。
• 實作 TF-IDF，並明確說明 TF 與 IDF 的確切定義，包括使用的平滑化或正規化方式。文件與查詢必須使用同一套由文件集合建立的詞彙表與 IDF 值；不得針對每次查詢重新擬合 IDF 模型。


4  搜尋與網頁介面

• 接受關鍵字查詢。使用倒排索引找出包含查詢詞彙的候選文件，再依 TF-IDF 向量之間的餘弦相似度進行排序。
• 依分數排序，最多回傳 10 筆相似度大於零的結果。必須正確處理空白查詢及詞彙表外的查詢，不得發生錯誤；沒有符合結果時，應顯示清楚的訊息。
• 使用 Flask 提供簡單的搜尋框與結果頁面。每筆結果必須顯示標題、網址、作為摘要的文字片段與分數。介面也必須顯示已建立索引的網頁數量。
• 摘要片段須使用純文字，長度約為 50–100 個英文字詞或 80–150 個中文字；若可用文字較短，則使用現有文字。
• 搜尋結果的連結僅限 HTTP/HTTPS 網址。展示時在本機執行即可，不要求公開部署。


5  實作範圍與限制

可以使用函式庫處理 HTTP 請求、HTML 解析、中文斷詞、SQLite 存取、數值運算及 Flask 網頁功能。倒排索引、TF-IDF 權重計算及餘弦相似度排序必須自行實作，而且檢索時必須實際使用自己建立的索引。

不得以代管式搜尋 API 或現成的搜尋引擎取代規定的元件。TfidfVectorizer 及類似的端到端 TF-IDF 實作，只能用來檢查計算結果，不得取代本作業要求的自行實作。請準備好解釋自己的程式碼，並以小型範例示範分數如何計算。


===== 第 3 頁 =====

6  必做的搜尋品質評估

Precision@5 是必做項目，不是加分項目。請針對已建立索引之文件集合的固定快照進行評估，讓報告中的結果可以重現。

• 準備 10 個彼此不同、與主題相關，且能代表合理使用者需求的測試查詢。在最終評估之前固定這些查詢；不得只挑選能產生良好結果的查詢。
• 為每個查詢簡短描述其資訊需求，並訂定相關性判定規則。根據文件內容，而非僅憑標題或摘要片段，將回傳的前五名文件逐一標記為相關（1）或不相關（0）。
• 將查詢、排名、文件 ID 或網址、相關性標記，以及簡短的判定理由儲存於評估檔案中。若情況允許，請另一位組員複核有疑義的判定。
• 分別計算每個查詢的 Precision@5，再回報全部 10 個查詢的算術平均值。若回傳結果少於五筆，缺少的位置應視為不相關；分母仍然是五。

Precision@5 = 前五個位置中相關文件的數量 / 5

範例：若前五筆結果中有三筆相關文件，則 Precision@5 = 3/5 = 0.60。若只回傳兩筆結果，而且兩筆都相關，則 Precision@5 = 2/5 = 0.40。

• 分析至少兩個表現不佳或失敗的查詢。說明可能原因，例如詞彙涵蓋不足、文字擷取品質不佳、斷詞問題或排序方法的限制，並提出改善建議。

評估部分的評分依據是正確性、可重現性及分析品質。由於各組的主題與文件集合不同，單憑較高的 Precision@5 並不保證能獲得高分。


選讀：理解 Recall 與 F1

召回率（Recall）是「檢索到的相關文件數量」除以「指定評估文件集合中的相關文件總數」。只標記回傳結果，無法確定這個分母。Recall 的計算範圍並不是整個網際網路上的所有相關網頁。

Recall 與 F1 不列為必做項目。若要回報這些指標，請使用範圍明確、且已完整判定相關性的評估文件集合，並說明檢索截斷位置（retrieval cutoff）。精確率（precision）與召回率（recall）必須針對同一組檢索結果計算。

F1 = 2 × precision × recall / (precision + recall)

若 precision 與 recall 都是零，則將 F1 回報為零。若某個查詢在評估文件集合中沒有任何相關文件，請說明如何處理此時無法定義的 recall。


7  繳交項目

• 可正常運作的原始碼：crawler.py、indexer.py、search.py、app.py，以及其他支援檔案。也接受功能相當的模組組織方式，但必須提供說明。
• README：包含安裝與執行命令、相依套件版本、種子網址、允許的主機、前處理方式，以及重現評估結果的步驟。
• JSON 或 SQLite 格式的資料集、儲存的索引檔案、爬取摘要／紀錄，以及查詢與相關性判定檔案。只繳交本作業所需的公開網頁內容；不得包含登入憑證或工作階段 Cookie。


===== 第 4 頁 =====

• 小組主要報告必須包含：系統架構圖；爬取統計資料（嘗試次數、有效網頁數、主機、失敗次數及平均文字大小）；前處理與評分方式的定義；3–5 個附圖的搜尋範例；全部 10 個查詢的評估結果；至少兩個表現不佳查詢的分析；實作過程中的挑戰；各組員的貢獻。
• 每位學生都必須另外繳交個人心得，說明自己在本專題中學到的內容與遇到的困難。
• 展示時，各組必須說明搜尋引擎的開發過程，進行 3–5 分鐘的現場操作展示，呈現搜尋引擎、具代表性的查詢，以及空白查詢或沒有符合結果的查詢，並說明遇到的挑戰與本專題的學習心得。


8  評分標準

項目：網頁爬蟲
分數：20
主要評分依據：正確遵守爬取範圍、robots.txt 與請求速率限制，儲存有用的文字內容，並保留紀錄。

項目：索引建立與前處理
分數：25
主要評分依據：適當的斷詞方式、正確的倒排索引，以及有清楚說明的 TF-IDF 計算方式。

項目：查詢與排序
分數：25
主要評分依據：實際使用索引、正確的餘弦相似度排序、前 K 筆結果（top-K），以及邊界情況的處理。

項目：搜尋品質評估
分數：15
主要評分依據：固定的查詢、相關性判定、正確的 Precision@5，以及失敗案例分析。

項目：網頁介面
分數：5
主要評分依據：可用的本機介面，以及安全的文字呈現方式。

項目：報告與展示
分數：10
主要評分依據：清楚的說明、可重現性、個人心得，以及可正常運作的展示。

總分：100


9  選做加分項目，最多加 10 分

加分適用於超出必做系統範圍、已完成且有清楚說明的功能：

• 使用相同查詢與相關性判定，比較 BM25 的表現：最多加 5 分。
• 使用詞彙位置資訊或驗證連續匹配的方式實作片語搜尋，或實作布林查詢：最多加 3 分。
• 測量查詢時間，清楚界定計時範圍並提供統計摘要：最多加 2 分。

加分項目不能取代必做項目。最高總分為 110 分。
